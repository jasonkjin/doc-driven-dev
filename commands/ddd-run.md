# ddd-run

参数:`$ARGUMENTS`

第一个 token 是槽位名或编号,其余是单元名。不带单元则跑全部未完成单元。多个单元且 plan 允许并行时并行派发。

先加载 `ddd` skill,读 `plan.md`、`context.md`、`requirement.md`、已有 `reports/`。

---

## 双重职责

1. **调度**:派 subagent 执行单元
2. **过滤**:收到 report 后判定偏离档位

第二项比第一项重要。**本命令是唯一持有 plan 全局视图的角色**,只有它判断得了"这个偏离会不会影响还没跑的单元"。

---

## 派发前

**单元的有效性和完成状态来自两个不同的地方:**

- `plan.md`:有哪些单元、哪些还有效。标为「已作废」或「已被 Tn 取代」的不派发
- `reports/`:哪些做完了。有对应文件即为完成,标记为 superseded 的除外

要跑的是「有效」减去「已完成」。

1. 按上述规则确定待跑单元
2. 检查依赖是否满足。依赖单元没有有效 report 就拒绝派发,说明原因
3. 需要独立 worktree 的先建好

**如果 plan 里存在标为需重做的单元,而它的下游单元显示已完成,停下来提示我。** 这通常意味着 `/ddd-plan` 的下游失效检查没走完。

---

## 注入给 subagent 的内容

**必须包含:**

- 该单元的定义与范围
- **该单元的验收标准**(不是 spec 的整体验收)
- 任务 `context.md`,尤其是「本任务内已确立的事实」
- 所属仓库的 `PROJECT.md`
- 相关的 spec 片段
- `requirement.md` 的技术方案一节(它是实现的前提,不该被推翻)
- report 模板(`projects/<repo>/templates/report.md`)
- 该单元「参考文档」字段声明的 `docs/` 文档全文。**没声明就不注入**

注入 `context.md` 是整个偏离传播机制生效的前提,漏了前面全白做。

docs 按声明注入,不要自作主张多给。subagent 的上下文有限,多塞一份调研材料就少一分留给 spec 和代码的空间。要不要给,`/ddd-plan` 已经判过了。

**必须传达的行为约束:**

- 如实记录验收执行结果,包括失败项。**无权判定合格与否**
- **不得修改 spec**。发现 spec 不可行就写进 report 的偏离段
- 偏离要写清影响范围,但**不判定档位**
- 没有偏离时写「无」是合法的,不要为了不显得敷衍而硬找东西写
- report 必须写入 `work/<槽位>/reports/<单元>.md`
- **产出的其他文档一律写入 `work/<槽位>/docs/`**,不要放在任务根目录、仓库里或临时目录;并在 report 末尾列出路径与一句话用途
- 语言规则见 skill 语言一节。其中**代码注释一节必须原样传达**:注释精简专业,禁 emoji、禁修辞、禁 markdown 强调符,且不得出现 spec、单元号、report、偏离、任务路径等本流程术语

---

## 收 report

**subagent 的工作过程你看不到,它结束时只返回一段总结。判档必须基于磁盘上的 report 文件,不能基于返回的总结。** 总结是自由发挥的,不保证偏离段完整。

所以:subagent 结束后去磁盘读文件,校验存在且符合模板。缺失或不合规就重新要一次,不能跳过。整套体系的状态传递全靠这个文件。

**顺带收 docs。** report 末尾列了新文档时,把它们登记进 `context.md` 的「参考文档」一节(五列格式见 skill 模板)。subagent 不登记,因为它看不到别的单元也在往同一张表里写。

report 没列但 `docs/` 下多出了文件,同样补登记并提一句。**不登记的文档等于不存在**,下一个会话不会知道它。

---

## 判档

读「与 spec 的偏离」一节,逐条判定(定义见 skill 偏离一节):

| 档 | 动作 |
|---|---|
| 局部 | 不动 |
| 跨单元 | 写进 `context.md` 的「本任务内已确立的事实」,标注来源单元 |
| 破坏性 | **停止,报告,不派下一个单元** |

破坏性偏离必须硬停。它意味着 spec 的前提塌了,后续单元可能整体要重排。让它写进 report 继续跑,会在很后面才暴露问题。

**并行时的边界情况:** 某单元产生跨单元偏离,而并行的另一单元已在跑。严格说这不该发生,`/ddd-plan` 判定可并行意味着判定过它们不互相影响,出现了说明并行判断有误。报告给我决定是让它跑完再看还是立即中止,不自动中止。

---

## 分批

单元多时建议分批跑,每批之间可以换会话。

理由:判档需要全局视图,跑很多单元之后你自己的上下文会涨,判断质量会下降。分批能保住这一点。

全量模式保留,适合单元少的任务。

---

## 输出

每个单元的结果、判档结论、`context.md` 的更新内容、以及是否可以继续。

有停止项时把停止原因放在最前面。
